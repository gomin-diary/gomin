# 고민일기 PR 작성

고민일기 저장소의 PR 제목·본문을 한국어 개조체로 작성한다. 현재 저장소의 [PR 작성 규칙](../../../docs/engineering/pull-requests.md)과 PR 템플릿을 확인하고, 사용자의 최신 지시를 우선 적용한다.

## 제목

- 형식: `[실제 Jira 이슈 키] 구체적인 최종 변경 결과`
- 실제 변경과 관련된 Jira 키 사용. 여러 이슈를 포함하면 관련 키 모두 표기
- 키는 작업 지시·브랜치·커밋·기존 PR에서 확인. 확인할 수 없으면 사용자에게 질문하며 임의 생성 금지
- 변경 결과를 한국어로 표현하고 “추가·수정·전환·분리” 등으로 마무리
- 커밋의 `feat:`, `docs:` 같은 타입 접두사는 제목의 필수 요소가 아님

## 본문

두 섹션으로 구성한다.

| 섹션 | 작성 내용 |
| --- | --- |
| `관련 작업` | 실제 Jira 이슈 키만 목록으로 표기 |
| `변경 내용` | 변경을 촉발한 문제와 최종 구현 결과를 간결한 목록으로 설명 |

- Jira 이슈 URL은 제목·본문에서 제외
- 최종 구현을 기준으로 작성하고, 진행 과정·폐기한 접근·향후 계획을 구현 결과처럼 서술하지 않음
- 설정 교체나 호출부 변경은 해당 변경 항목에 포함. 별도 `적용 범위`·`호환성 변경` 섹션을 만들지 않음
- 기능 테스트를 언급할 때는 실제 확인한 동작을 `변경 내용`에 포함. 별도 `검증` 섹션은 만들지 않음
- 테스트 개수·명령어·통과 기록과 미검증·생략 항목은 본문에서 제외
- 다른 기능이나 이슈가 담당하므로 구현하지 않았다는 범위 제외 설명은 생략
- 배포 완료나 Jira 작업 전체 완료로 확대하여 표현하지 않음

## 개조체

- 각 항목을 짧고 완결된 구로 작성하고 “추가·수정·정의·연결·보관·검증” 같은 명사형으로 마무리
- “추가합니다”, “수정했습니다”, “테스트했습니다” 같은 서술형 종결 대신 “추가”, “수정”, “동작 검증” 사용
- 항목마다 하나의 목적을 중심으로 작성하고, 같은 설명을 제목과 본문에 반복하지 않음

## 작성 예시

제목: `[GOMIN-74] 대화·컬렉션 DB 마이그레이션과 ERD 추가`

```markdown
## 관련 작업

- GOMIN-74

## 변경 내용

- 대화·요약·그림일기 결과와 컬렉션 저장을 연결하는 신규 테이블 6개 및 Supabase 마이그레이션 추가
- 중복 저장 방지 제약과 회원·대화 소유권 검증 정의
- 생성 완료 시각의 한국 날짜를 기준으로 그림일기 날짜 자동 계산
- ERD와 ID 생성·재시도 흐름 문서화 및 문서 목록 연결
- 중복 요청·소유권 불일치 거절과 한국 날짜 경계 동작 검증
```

예시의 Jira 키와 변경사항은 형식을 보여주기 위한 값이다. 실제 작업에서 확인한 내용으로 교체한다.

## 반영과 확인

- 초안 요청이면 제목·본문 초안 작성. PR 생성·수정 요청이면 해당 PR에 반영 후 제목·본문 재조회
- 기존 PR 수정 시 요청한 부분을 변경하고, 무관한 본문·필드 보존
- CLI로 여러 줄 본문을 전달할 때는 임시 파일과 `--body-file` 사용. 실제 줄바꿈 유지
- PR 생성 시 현재 작업에 PR을 연결하는 도구가 있으면 생성한 PR 연결
- 반영 후 Jira 키, 두 섹션의 구성, 개조체, 최종 변경과의 일치 여부 확인
