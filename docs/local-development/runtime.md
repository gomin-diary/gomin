# 개발 서버 실행

[설치](setup/README.md)를 마친 뒤 저장소 루트에서 실행합니다.

```sh
npm run dev
```

## 대상별 시작·재시작

| 명령 | 동작 |
| --- | --- |
| `npm run dev` / `npm run dev:all` | 프론트엔드와 백엔드 시작·재시작 |
| `npm run dev:frontend` | 프론트엔드만 시작·재시작 |
| `npm run dev:backend` | 백엔드만 시작·재시작 |

실행기가 없으면 현재 터미널이 개발 터미널이 됩니다. 이미 실행 중이면 다른 터미널의 명령은 기존 실행기에 요청을 전달하고 결과를 출력한 뒤 끝납니다. 서버 로그는 기존 개발 터미널에 계속 표시됩니다. 동시에 들어온 요청은 순서대로 처리합니다.

요청 처리 성공은 프로세스 시작을 뜻합니다. HTTP 요청을 받을 준비가 됐는지는 Next.js·Uvicorn의 로그를 확인하세요. 실행 이후 앱이 오류로 종료되면 해당 서버의 종료를 알리며 실행기와 다른 서버는 유지합니다.

## 실행 순서

1. 선택한 앱의 의존성을 확인합니다.
2. 백엔드가 포함되면 로컬 Supabase를 시작하고 미적용 마이그레이션을 적용합니다.
3. 로컬 API URL과 서버 키를 조회해 백엔드 환경변수로 전달합니다.
4. 선택한 앱이 실행 중이면 해당 프로세스와 하위 프로세스를 종료합니다.
   프론트엔드는 `.next/dev/lock`의 실제 잠금도 확인합니다. 포트를 열지 않은 기존 Next.js 개발 서버가 잠금을 보유하고 있으면 해당 PID를 출력하고 종료한 뒤 잠금 해제를 기다립니다. 잠금 파일을 임의로 삭제하지 않습니다.
5. 선택한 앱의 포트(프론트엔드 3000, 백엔드 8000)를 점유한 프로세스가 있으면 PID를 출력하고 종료합니다. 포트가 해제되면 선택한 앱을 시작합니다.

재시작은 의존성을 다시 설치하지 않습니다. 패키지를 변경했다면 실행기를 종료하고 `./scripts/setup.cmd`를 다시 실행하세요.

선택한 포트를 사용하는 프로세스는 다른 프로젝트의 서버라도 종료합니다. macOS·Linux에서는 `lsof`로 TCP 리스너를 찾고 정상 종료를 요청하며, 5초 후에도 포트가 사용 중이면 조회한 프로세스를 강제 종료합니다. Windows에서는 `netstat`로 TCP 리스너를 찾고 `taskkill /T /F`로 해당 프로세스와 하위 프로세스를 종료합니다. 조회 도구가 없거나 종료 권한이 부족하거나 포트가 해제되지 않으면 오류로 중단합니다.

## 종료

개발 터미널에서 `Ctrl+C`를 누르면 진행 중인 준비 작업을 취소하고 관리하는 앱 서버를 정리합니다. Supabase 컨테이너는 다음 실행을 위해 유지합니다.

```sh
npm run supabase:stop
```

일반 중지는 로컬 데이터를 보존합니다. 데이터를 유지해야 한다면 `--no-backup` 옵션이나 Docker 볼륨 삭제를 사용하지 마세요.

실행 중에는 `.dev/`를 삭제하지 마세요. 실행기에는 인증 토큰으로 보호한 루프백 제어 소켓이 있고, `.dev/`에는 PID 잠금 파일과 연결 정보가 저장됩니다. 정상 종료 시 정리하며, 비정상 종료 후에는 남은 PID가 실행 중인지 확인합니다.
