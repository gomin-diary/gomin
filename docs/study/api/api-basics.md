# API란 무엇일까

함수를 사용할 때는 이름, 전달할 값, 반환값을 알아야 한다. 함수 내부를 모두 읽지 않아도 그 약속에 맞춰 호출하면 된다. API도 프로그램이 다른 기능을 사용하는 방법을 정한 약속이다.

API는 Application Programming Interface의 줄임말이다. 여기서 인터페이스는 서로 연결되는 지점과 사용 규칙을 뜻한다. 화면의 버튼처럼 사람이 사용하는 인터페이스와 달리 API는 프로그램이 기능을 호출할 때 사용한다.

## API가 꼭 인터넷 통신일까

API는 인터넷 통신보다 넓은 개념이다. 운영체제가 파일을 읽는 기능, 라이브러리가 제공하는 함수, 브라우저의 `fetch`도 API다.

웹 개발에서 “백엔드 API를 호출한다”고 말할 때는 대개 HTTP로 서버의 기능을 사용하는 일을 뜻한다. 브라우저의 기능을 호출하는 Web API와 서버에 요청을 보내는 HTTP API는 구분해서 이해해야 한다.

API를 사용하면 호출하는 쪽과 구현하는 쪽이 약속을 기준으로 협업할 수 있다. 서버 내부의 데이터 저장 방법을 바꾸더라도 주소·입력·응답 약속을 유지하면 화면 코드를 그대로 사용할 여지가 생긴다. 응답 필드를 없애거나 의미를 바꾸면 호출하는 쪽도 영향을 받는다.

## HTTP API의 약속

| 항목 | 확인할 내용 |
| --- | --- |
| 주소와 메서드 | 어디에 어떤 요청을 보내는가 |
| 입력 | 경로·쿼리·헤더·본문 중 어디에 어떤 값을 넣는가 |
| 인증·권한 | 누가 호출할 수 있고 어떤 인증 정보가 필요한가 |
| 성공 응답 | 어떤 상태 코드와 데이터를 반환하는가 |
| 실패 응답 | 어떤 상황에 어떤 오류를 반환하는가 |

엔드포인트는 API에 요청을 보내는 접점이다. 실무에서는 `GET /api/v1/health`처럼 메서드와 경로를 묶어 가리키기도 한다. 같은 경로라도 `GET`과 `POST`는 서로 다른 처리를 요청한다.

API 명세는 이 약속을 문서로 적은 것이다. OpenAPI[^openapi]는 HTTP API 명세를 표현하는 표준 형식이다. Swagger UI는 그 명세를 읽기 좋은 화면으로 보여주고 요청을 시험할 수 있게 해주는 도구다. 명세와 화면 도구는 역할이 다르다.

## 하나의 요청을 따라가 보기

우리 프로젝트에는 로그인 없이 상태를 확인하는 API가 있다.

```http
GET /api/v1/health
```

성공하면 HTTP `200`과 다음 JSON을 반환한다.

```json
{
  "success": true,
  "data": { "status": "ok" },
  "error": null
}
```

호출하는 쪽은 `data.status`를 읽어 결과를 확인한다. 이 API는 DB를 조회하지 않는다. DB 연결 확인은 별도 엔드포인트인 `GET /api/v1/health/db`가 맡는다.

요청을 보내는 주체가 꼭 화면일 필요는 없다. 터미널의 HTTP 도구, 다른 서버, 모니터링 서비스도 같은 약속을 사용해 요청할 수 있다.

## 우리 프로젝트에서는

백엔드의 [health.py](../../../backend/app/api/routes/health.py)에 상태 확인 API가 있다. 다른 API도 `backend/app/api/routes/`에 기능별로 나뉘어 있다.

프론트엔드는 공통 함수 `apiFetch`로 백엔드를 호출한다. 이 함수가 API 주소를 만들고 공통 응답 형식을 확인한다. 오류는 화면에서 처리할 수 있는 형태로 바꾼다. 개별 화면에서 같은 통신 처리를 반복하지 않도록 모은 것이다.

FastAPI는 코드에 선언한 경로와 데이터 모델로 OpenAPI 명세를 만든다. 현재 기본 설정에서는 백엔드의 `/openapi.json`에서 명세를, `/docs`에서 Swagger UI를 제공한다. 프론트엔드의 `/docs`는 지금 읽는 Markdown 문서 영역이므로 어느 서버의 주소인지 함께 확인한다.

## 자주 헷갈리는 점

API가 공개된 주소라고 해서 모든 호출자가 같은 권한을 얻는 것은 아니다. API는 요청마다 입력과 권한을 확인할 수 있다. 화면에서 버튼을 숨기는 것만으로 서버의 작업을 막을 수는 없다.

SDK는 API 사용을 돕는 라이브러리 묶음이다. 우리 백엔드의 Supabase Python SDK도 외부 API 호출을 코드에서 다루기 쉽게 감싼다. SDK를 사용해도 통신 실패나 권한 오류는 발생할 수 있다.
