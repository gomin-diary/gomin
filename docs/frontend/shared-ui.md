# 공용 화면과 배경 매핑

## 경로와 메뉴

`frontend/src/lib/shared-pages.ts`가 메뉴 정의와 페이지별 배경을 관리한다. `PageShell`은 장식용 배경, 브랜드, 메뉴, 본문 건너뛰기 링크를 제공한다. `SiteMenu`는 Next.js Link와 현재 URL을 사용하며 활성 링크에 `aria-current="page"`를 설정한다. 하위 경로는 부모 메뉴를 활성화한다.

| 페이지 | 경로 | PC 메뉴 | 모바일 메뉴 |
| --- | --- | --- | --- |
| 홈 | `/` | 상단, 홈 활성 | 하단, 홈 활성 |
| 가이드 | `/guide` | 상단, 가이드 활성 | 하단, 가이드 활성 |
| 컬렉션(보관함) | `/collection` | 상단, 컬렉션 활성 | 하단, 컬렉션 활성 |
| 로그인 | `/login` | 상단, 활성 항목 없음 | 숨김 |
| 회원가입 | `/signup` | 상단, 활성 항목 없음 | 숨김 |
| 대화 | `/talk` | 숨김 | 숨김 |

지정 경로는 준비 안내 화면을 제공한다. 인증·대화·가이드·컬렉션의 업무 기능과 홈의 완성 콘텐츠는 별도 작업 대상이다. 홈에서 가이드와 대화로, 로그인에서 회원가입으로 이동할 수 있다. 각 준비 화면에는 홈으로 돌아가는 링크가 있다.

768px 이상에서는 PC 상단 메뉴, 미만에서는 모바일 하단 메뉴를 사용한다. 모바일 메뉴는 96px에 하단 안전영역을 더한다. 본문에도 같은 높이와 여백을 확보하며, 링크는 같은 너비로 배치한다. Figma 홈 모바일의 일러스트 메뉴는 별도 홈 콘텐츠이고 이 공용 하단 메뉴와 구분한다.

## 배경 매핑

아래 이미지 이름에는 `/images/backgrounds/` 접두사와 `.avif` 또는 `.webp` 확장자가 붙는다. 모든 배포 자산은 `frontend/public`에 포함되며 로컬 `figma/`에 런타임 의존하지 않는다.

| 페이지 | PC 자산 / Figma 노드 | 모바일 자산 또는 색상 / Figma 노드 |
| --- | --- | --- |
| 홈 | `home-desktop` / `39:48` | `home-mobile` / `23:3` |
| 가이드 | `login-desktop` / `25:2` (`82:835`에서 재사용) | `#ffffff` / `56:96` |
| 컬렉션 | `collection-desktop` / `65:114` | `#0b0e0d` / `84:1065` |
| 로그인 | `login-desktop` / `25:2` | `login-mobile` / `23:2` |
| 회원가입 | 로그인과 동일 / `84:1285` | 로그인과 동일 / `84:1362` |
| 대화 | `talk-desktop` / `85:1433` | `talk-mobile` / `85:1434` |

PC 이미지 규격은 2560×1440, 모바일은 1440×3120이다. 홈 PC는 헤더 아래 영역에 배경을 표시하며 나머지 이미지 배경은 화면 전체를 채운다. `picture`와 media 조건으로 기기에 맞는 파일을 선택하고 AVIF 미지원 시 WebP로 폴백한다. `object-fit: cover`로 원본 비율을 유지하므로 화면 비율에 따라 가장자리 일부는 잘릴 수 있다. 배경은 본문 뒤에 배치하고 포인터와 접근성 트리에서 제외한다. 준비 안내 카드는 밝은 배경으로 텍스트 대비를 확보한다.

모바일 가이드와 컬렉션에는 사진 배경을 추가하지 않는다. 각 원본 화면의 단색 배경을 사용한다. PC 가이드의 콘텐츠용 밝은 베일, 대화의 조용한 배경 오버레이는 해당 업무 화면 구현에서 적용할 수 있다.

## 자산 출처

[Figma 디자인](https://www.figma.com/design/t66NuRwO9mgwGbLTc2allQ)의 현재 화면 구조와 [PC 메뉴](https://www.figma.com/design/t66NuRwO9mgwGbLTc2allQ?node-id=28-69)를 MCP로 확인했다. 추가 조회는 Starter MCP 호출 한도로 제한되어 Figma 데스크톱 앱에서 모바일 메뉴, 배경 컴포넌트와 단색 값을 확인했다. PC 및 대화 배경은 같은 앱에서 원본 컴포넌트를 PNG 1×로 내보내 AVIF/WebP로 변환했다. 이미지 원본에 없는 내용을 합성하지 않았다.

`/images/navigation/`의 32×32 SVG 6개는 Figma 모바일 메뉴를 만든 로컬 원본의 SVG 정의를 그대로 파일로 재사용한다. 홈·책·컬렉션 아이콘의 활성/비활성 모양과 색상을 유지한다. `/images/icons/leaf.svg`는 기존 브랜드 자산을 재사용한다. 브랜드·메뉴·본문 글꼴은 `frontend/public/fonts/Ongleip-konkon.ttf`를 로컬 제공하는 온글잎 콘콘체를 사용한다.

## 검증 기준

- `npm --prefix frontend run lint`, `npm --prefix frontend run typecheck`, `npm --prefix frontend run build`
- PC(2560×1440, 1440×900), 모바일(390×844, 320×568), 가로 화면(844×390)에서 메뉴 이동, 현재 메뉴, 가로 넘침, 이미지 디코딩, 콘텐츠와 메뉴 겹침 확인
- 로그인·회원가입의 모바일 메뉴 숨김, PC의 활성 항목 없음, 대화 메뉴 숨김 확인
- 키보드 Tab 포커스, 본문 건너뛰기, 긴 콘텐츠 스크롤, 새로고침과 페이지 전환 확인

프로덕션 Chrome에서 여섯 경로 × 다섯 화면 크기, 총 30개 조합의 이동·활성 메뉴·배경 매핑·이미지 로딩·새로고침·넘침을 확인했다. 본문 건너뛰기와 키보드 포커스, AVIF 소스를 제거한 WebP 폴백, 긴 본문 스크롤도 통과했으며 브라우저 런타임 오류는 없었다. 모바일에서 노출되는 메뉴 아이콘은 32×32, 하단 메뉴는 안전영역이 없는 환경에서 96px임을 확인했다.

실제 iOS/Android 기기에서의 안전영역과 Safari 렌더링, 전체 업무 화면과 배포 서비스의 동작은 확인하지 않았다. 프로젝트의 기존 다중 잠금 파일에 대한 Next.js 경고는 공용 화면 범위 밖이므로 유지한다.
