# PR 작성 규칙

## 제목

PR 제목은 Jira 작업 번호와 최종 변경 결과를 포함한다.

```text
[GOMIN-53] Resend HTTPS API 기반 이메일 발송으로 전환
```

- 여러 Jira 작업을 포함하면 관련 작업 번호를 모두 적는다.
- 실제 작업 번호를 사용하며 번호를 추측하거나 임의로 생성하지 않는다.
- 한글로 변경 결과를 구체적으로 표현한다. 커밋 제목의 타입 접두사는 필수가 아니다.

## 본문

기존 PR의 `변경 내용`, `적용 범위` 또는 `호환성 변경` 형식을 유지하되
`관련 작업`과 `검증`을 포함한다. 변경을 촉발한 문제와 결과를 먼저 설명한다.

- **관련 작업:** Jira 작업 번호와 해당 이슈 링크를 적는다.
- **변경 내용:** 최종 구현과 변경 이유를 설명한다.
- **적용 범위 / 호환성 변경:** 필요한 설정 교체나 호출부 변경을 명시한다.
- **검증:** 실제 확인한 검사, 생략한 검사와 아직 확인하지 못한 배포·서비스 동작을 구분한다.

로컬 테스트 통과만으로 실제 배포나 Jira 작업 전체가 완료되었다고 작성하지 않는다.
비밀값은 제목·본문·검증 기록에 포함하지 않는다.
