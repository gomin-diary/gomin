# PR 작성 규칙

## 제목

PR 제목은 Jira 작업 번호와 최종 변경 결과를 포함한다.

```text
[GOMIN-53] Resend HTTPS API 기반 이메일 발송으로 전환
```

- 여러 Jira 작업을 포함하면 관련 작업 번호를 모두 적는다.
- 실제 작업 번호를 사용하며 번호를 추측하거나 임의로 생성하지 않는다.
- 한글로 변경 결과를 구체적으로 표현한다. 커밋 제목의 타입 접두사는 필수가 아니다.

## 본문

변경을 촉발한 문제와 최종 구현 결과를 간단히 설명한다.

- **관련 작업:** Jira 작업 번호만 적고 이슈 링크나 주소는 넣지 않는다.
- **변경 내용:** 최종 구현과 변경 이유를 설명한다.
- **적용 범위 / 호환성 변경:** 필요한 설정 교체나 호출부 변경이 있을 때만 적는다.
- 별도의 `검증` 섹션은 만들지 않는다. 테스트 내용이 필요하면 해당 기능의 어떤 동작을 테스트했는지만 변경 내용에 적는다.
- 테스트 개수·명령어·통과 기록, 미검증·생략 항목은 PR 본문에 나열하지 않는다.
- 다른 기능이나 Jira 작업에서 담당하기 때문에 구현하지 않았다는 범위 제외 설명은 넣지 않는다.

실제 확인한 기능 테스트만 기재하고 배포나 Jira 작업 전체가 완료되었다고 추정하지 않는다.
비밀값은 제목·본문에 포함하지 않는다.
